| --- | ----- | ----------------------- | ----------------------------------------------------------------------------------------- | --------------- |

### 1-1. 불안 해소 평가 (2026-10-05 추가)

B-4~B-6은 "틀리지 않았는가"만 잰다. 질문 도우미의 목적(보호자가 결과의 의미를 모른 채 쌓는 불안을 줄임)은 아래 항목으로 함께 잰다. 기준선 판정(PoC 완료 조건)에는 넣지 않고 평가 리포트에 기록한다.

| ID  | 항목             | 대상                                       | 채점                | 통과 기준                                |
| --- | ---------------- | ------------------------------------------ | ------------------- | ---------------------------------------- |
| R-1 | 질문에 직접 답함 | `explain`·`diagnosis` 문항                 | 수동(사용자), 예/아니오 | 프롬프트 v1 대비 상승                   |
| R-2 | 다음 단계 안내   | 노트에 저장된 문항                         | 자동                | 전부                                     |
| R-3 | 공감 문장        | `explain`·`diagnosis` 문항                 | 수동(사용자), 예/아니오 | 프롬프트 v1 대비 상승, 안심 문구 0건(B-4) |
| R-4 | 범위 밖 오분류   | 보고서 권고 행동 질문(`tags: report_action`) | 자동                | route = `redirect` 0건                   |

- R-1: 질문이 묻는 것(예: "기준선 바로 아래면 사실상 같은가")에 보고서 사실로 답했거나, 답할 수 없는 부분이 무엇인지 밝혔는가. 숫자만 다시 말하고 걱정을 비켜 가면 '아니오'.
- R-2: 응답에 `note_saved` 문구(질문이 상담사에게 전달된다는 안내)가 있는가. 코드가 붙이는 문구라 자동으로 확인한다.
- R-3: 보호자의 마음을 받는 문장이 있는가. 아이 상태에 대한 판단·안심 문구("괜찮다", "~라는 뜻은 아니다")가 있으면 '아니오'(`CLAUDE.md` G-01).
- 비교 방법: 같은 평가셋을 프롬프트 v1과 v2로 실행해 R-1·R-3 '예' 비율을 리포트에 나란히 적는다.

## 2. 공통 전제

### 2-1. 입력 계약

- PoC 코드는 `CLAUDE.md` 8-1 공통 뼈대를 따르는 payload를 입력으로 받는다. 원천 데이터 변환은 별도 작업이다.
- PoC가 사용하는 최소 필드:
  - `scores[]`: `id`, `scale`, `name`, `t`, `percentile`(null 허용), `range`
  - `findings[]`: `id`, `section`, `scale`(null 허용), `text`
- 식별 정보(이름, 생년월일, 학년 등)는 payload 밖 `subjects` 테이블에 따로 둔다(2-4). `subjects`는 마스킹(PoC2-02)만 읽고, 프롬프트·화면 요약에 넣지 않는다(G-09).

### 2-2. 판정 기준 정의 (`assessment_types.definition`)

범위 판정은 이 정의만 읽는다(G-02, G-12). PoC에서는 CBCL 정의 1개를 시드로 넣는다.

```json
{
  "range_labels": {
    "normal": "또래 평균 범위",
    "borderline": "관찰 권고 범위",
    "clinical": "전문 상담 권고 범위",
    "not_administered": "미실시"
  },
  "groups": {
    "composite": {
      "direction": "higher_is_worse",
      "borderline_min": 60,
      "clinical_min": 63
    },
    "syndrome": {
      "direction": "higher_is_worse",
      "borderline_min": 60,
      "clinical_min": 70,
      "t_floor": 50
    }
  },
  "scales": {
    "internalizing": { "group": "composite" },
    "externalizing": { "group": "composite" },
    "total": { "group": "composite" },
    "attention": { "group": "syndrome" }
  }
}
```

- `scales`에는 실제 척도 키 전체를 넣는다(위는 일부). 척도 키는 변환 작업의 `scale` 값과 맞춘다.
- `lower_is_worse`(사회능력)는 판정 로직이 지원하되, PoC 시드에서는 사회능력 기준을 넣지 않는다(샘플 기준 값이 가정이므로).
  - `lower_is_worse` 그룹의 기준 키는 `borderline_max`, `clinical_max`다(T ≤ `clinical_max` → clinical, T ≤ `borderline_max` → borderline).
- 판정 기준이 없는 척도(KCBCL 시드의 특수척도·사회능력)는 `group` 없이 `direction`만 둔다. 예: `"total_competence": {"direction": "lower_is_worse"}`. `direction`은 백분위 문장(PoC1-02)의 방향에만 쓴다(2026-10-04 결정).
- `t_floor`(선택): 그 그룹의 T점수 하한. 증후군 척도는 50(백분위 50 이하는 50T, `CLAUDE.md` 8-2). 백분위 문장(PoC1-02)에만 쓴다(2026-10-05 추가).
- `group`이 없는 척도(또는 `scales`에 없는 척도)는 판정하지 않는다. 판정 결과는 '정의 없음'이고 B-2 대조에서 제외한다(2026-10-03 결정). 화면 표시는 PoC1-04의 '카드 없음' 처리를 따른다.
- `report_sections`(2026-10-05 추가, PoC1-09): 원보고서의 섹션 순서와 제목. 결과 화면 배치에만 쓴다.

```json
"report_sections": [
  {"key": "H",   "title": "기본 정보"},
  {"key": "I",   "title": "Ⅰ. 사회능력 척도"},
  {"key": "II",  "title": "Ⅱ. 문제행동 종합 지표"},
  {"key": "III", "title": "Ⅲ. 증후군 척도 프로파일",
   "subgroups": [{"title": "내재화 증후군", "scales": ["withdrawn", "somatic", "anxdep"]},
                 {"title": "혼합 증후군",   "scales": ["socimm", "thought", "attention"]},
                 {"title": "외현화 증후군", "scales": ["delinquent", "aggressive"]}]},
  {"key": "IV",  "title": "Ⅳ. 특수 척도"},
  {"key": "V",   "title": "Ⅴ. 주요 관찰 소견"},
  {"key": "VI",  "title": "Ⅵ. 종합 해석"},
  {"key": "VII", "title": "Ⅶ. 보호자 참고 의견"},
  {"key": "C",   "title": "해석 시 유의사항"}
]
```

  - `key`는 항목 id의 접두어(첫 `.` 앞, `CLAUDE.md` 8-1)와 같다. `subgroups`(선택)는 그 섹션 점수의 소제목 묶음이다.

### 2-3. 기준 샘플

- 데모와 **기준 평가**는 **고정된 샘플 1건**을 기준으로 한다(평가셋 질문이 특정 점수를 전제하므로). 여러 샘플에서 통하는지는 **다샘플 평가**(6-2)로 따로 잰다(2026-10-06).
- 선정 조건: 종합척도에 준임상 이상 1개 이상, 증후군 척도에 정상·준임상·임상이 모두 있고, 미실시 항목이 1개 이상 있는 샘플.
- **기준 샘플: `data/kcbcl_results/035.json`** (`R-KCBCL_4_17-035`, 남아 만 9세 6개월, 2026-10-03 확정)
  - 종합척도: 내재화 56 normal · 외현화 64 clinical · 총 문제행동 69 clinical
  - 증후군: 사회적 미성숙 80 clinical · 주의집중 문제 66 borderline(백분위 95) · 공격성 66 borderline · 나머지 5개 normal(비행 50T, 백분위 null)
  - 미실시: 성문제. 판정 기준(group) 없는 실시 척도: 정서불안정 66, 사회성 42 · 학업수행 43 · 총 사회능력 40
  - 보호자 의견 3건(`VII.1` 사회적 미성숙, `VII.2` 주의집중 문제, `VII.3` 정서불안정)
  - 선정 이유: PoC2-05 예시(주의집중 문제 T=66, 관찰 권고 범위) 재현, 정상·준임상·임상·백분위 null·미실시를 한 건에 포함, 보호자 의견에 위험 표현 없음(B-5가 질문으로만 결정됨)

### 2-3-1. 공개 샘플 범위와 문장 (2026-10-06 사용자 결정)

- 생성 스크립트는 같은 seed로 100건을 만들되(점수 재현성 유지), **평가에 쓰는 10건만** 내보낸다: 기준 샘플 035 + 다샘플 평가 샘플(6-2, `eval/samples.json`). 번호와 점수는 축소 전과 같다.
- 원천 데이터의 서술 문형 가운데 회사 제공 보고서(2-4-1, 공유 금지)와 겹치던 문장은 자체 문장으로 바꿨다. 기준: 공개 파일에 회사 제공 보고서 문장과 15자 이상 같은 구간이 없을 것. 보고서 용어(낱말)는 일반 용어로 보고 남긴다(용어사전 연결 유지).
- B-1·B-2·B-3의 '샘플 전체'는 공개 10건이다.

## 3. PoC-1 쉬운 말 결과 (M1)

### PoC1-01 범위 판정 [G-02] → B-2

```
Given 판정 기준 정의(2-2)
When 종합척도 T가 59, 60, 62, 63이면
Then 각각 normal, borderline, borderline, clinical 로 판정한다

Given 판정 기준 정의(2-2)
When 증후군 척도 T가 59, 60, 69, 70이면
Then 각각 normal, borderline, borderline, clinical 로 판정한다

Given 적재된 샘플 전체
When 정의(2-2)의 scales에서 group이 있는 scores 항목을 판정하면
Then 판정 결과가 payload의 range와 모두 같다 (다르면 테스트 실패 + 해당 id 출력)
 And group이 없는 항목은 판정하지 않고 대조에서 제외한다

Given 증후군 척도 하한 50T
When 판정하면
Then normal 이다

Given direction = lower_is_worse 인 그룹 정의
When T가 clinical_max, borderline_max, borderline_max+1 이면
Then 각각 clinical, borderline, normal 로 판정한다

Given t가 null인 항목
When 판정하면
Then not_administered 를 반환한다
```

### PoC1-02 숫자 표시 [G-03] → B-1

```
Given 기준 샘플
When 결과 화면 데이터(view model)를 만들면
Then 모든 T점수·백분위는 payload의 해당 id 값에서 복사된 값이다
 And 백분위 문장은 척도의 direction(2-2)에 맞는 content 문장을 쓴다
 And percentile이 null이고 T가 그룹의 t_floor와 같으면(증후군 척도 하한 50T) 하한 설명 문장을 쓴다
 And percentile이 null이고 T가 하한이 아니면(원보고서에 백분위가 없음) 백분위 문장 없이 숫자만 쓴다
```

- 백분위 문장은 content 템플릿으로 만든다. 문장에 숫자를 쓰지 않는다는 7장 규칙에 맞추기 위해 '또래 100명 중' 표현을 쓰지 않는다(2026-10-04 결정).
  - `higher_is_worse`: `상위 약 {rank_from_top}%` (`rank_from_top` = 100 − 백분위, 코드가 계산)
  - `lower_is_worse`: `하위 약 {percentile}%` + 점수가 낮을수록 어려움이 크게 보고되었다는 방향 안내 문장
  - 백분위 null(하한): 이 척도에서 표시되는 가장 낮은 점수이며 또래 평균과 비슷하거나 낮다는 뜻, 이 구간은 백분위를 따로 계산하지 않는다는 문장
  - direction이 없는 척도: 백분위 문장 없이 숫자만 표시

### PoC2-04 의도 분류

```
Given 키워드 규칙으로 의도가 하나로 정해지는 질문
When 분류하면
Then LLM을 호출하지 않고 그 의도를 쓴다

Given diagnosis 키워드가 걸리는 질문 (다른 의도 키워드가 함께 걸려도)
When 분류하면
Then LLM을 호출하지 않고 diagnosis 로 정한다

Given 키워드 규칙으로 정해지지 않는 질문 (아무 의도에도 안 걸리거나, diagnosis 없이 두 개 이상에 걸림)
When 분류하면
Then 분류 LLM을 호출해 JSON {intent, confidence} 를 받고
 And confidence가 임계값 미만이거나 JSON이 깨지면 route = safe 로 보낸다
```

- 임계값: 임시 0.7(가정, `config.INTENT_CONFIDENCE_THRESHOLD`). 평가셋 1차 실행 후 결정.
- 분류 LLM 입력은 마스킹된 질문만(보고서 없음, G-09). JSON이 깨지거나, intent가 의도 코드(2-5) 밖이거나, confidence가 0~1 밖이면 route = safe.
- LLM이 crisis로 분류하면 신뢰도와 무관하게 route = crisis (PoC2-03 두 번째 수용 기준과 겹칠 때 안전 쪽 해석, 2026-10-04 사용자 확인).
- diagnosis 우선(2026-10-04 결정): 진단 신호가 있는 질문을 LLM 분류에 맡기지 않는 보수적 처리. "ADHD가 뭐예요?"처럼 설명형과 겹쳐도 안전 응답 + 노트 저장으로 보낸다.
- 의도 키워드는 모든 검사가 공유하므로 특정 검사의 척도 이름을 넣지 않는다(G-12). 질문 속 척도는 payload `scores[].name`으로 찾는다.
- 분류 프롬프트 v2(2026-10-05): `explain`·`out_of_scope` 정의를 2-5의 기준으로 고치고, 보고서 권고 행동 질문 예시(“교사용 질문지를 병행하라는데 어디서 받나요?” → `explain`)를 넣는다. 섞인 의도의 우선순위(crisis → diagnosis → parenting → out_of_scope → explain)는 유지한다.

```
Given 보고서에 적힌 권고 행동의 방법·시기를 묻는 질문 (예: "정기적으로 다시 검사하라는데 몇 달 뒤에 하나요?")
When 분류하면
Then route ≠ redirect 이다 (R-4)
```

### PoC2-05 안전 응답 [G-05]

```
Given intent ∈ {diagnosis, parenting} 또는 신뢰도 미달
When 처리하면
Then 응답 생성 LLM 호출이 0회이고
 And 응답은 미리 만든 문장을 코드가 조립한 것이며(아래 순서)
 And 질문 노트에 1건 저장된다(type = intent)

Given 질문에서 척도를 2개 이상 찾음 (예: "위축과 우울/불안이 …")
When 안전 응답을 조립하면
Then 찾은 척도 가운데 T점수와 범위 이름이 있는 것을 최대 SAFE_MAX_SCALES개까지 모두 사실 문장으로 넣는다

Given 안전 응답 (종류 무관)
When 노트에 저장하면
Then 응답에 note_saved 문구가 들어 있다 (R-2)
```

조립 순서(2026-10-05, 불안 해소 1단계). 문장은 모두 `content/`의 미리 만든 문장이고, 숫자·인용은 코드가 payload에서 채운다(G-03, G-04).

1. 공감 문장: 종류별 템플릿의 `empathy`. 보호자의 마음을 받는 문장만 쓴다. 아이 상태 판단·안심 문구는 쓰지 않는다(`CLAUDE.md` G-01, 7장).
2. 척도 사실: 찾은 척도마다 "보고서에서 {scale_name} 점수는 T점수 {t}점으로, {range_label}에 있습니다."
3. 보고서 인용: 2에 넣은 첫 척도에 연결된 `type = observation` 서술(`scale`이 같은 것)의 첫 줄을 그대로 인용하고, 그 서술 id를 근거 칩·노트 관련 항목에 더한다. 진단명 사전·금칙 표현에 걸리면 넣지 않는다(B-4). 첫 줄은 관찰 사실, 둘째 줄부터는 해석인 경우가 많아 첫 줄만 쓴다.
4. 본문: 종류별 템플릿의 `body`(무엇을 상담에서 다루는지).
5. 선별 검사 안내(`diagnosis`만): 검사가 진단이 아니라 선별 검사라는 고정 문구. 결과 화면의 고정 문구(PoC1-07)와 같은 사실이다.
6. `note_saved`: 질문이 상담 노트에 저장되어 상담사가 상담 전에 확인한다는 안내(다음 단계).
7. 준비 행동: 궁금한 장면을 언제·어떤 상황이었는지 메모해 두라는 안내. `low_confidence`는 대신 다시 물어보는 방법을 안내한다.

예시: "ADHD인가요?" (기준 샘플) → 공감 + 주의집중 문제 T점수 66점, 관찰 권고 범위 + `V.attention` 첫 줄 인용 + 진단은 상담에서 다룬다 + 선별 검사 안내 + 노트 저장·상담사 확인 + 장면 메모 안내.

- 질문 속 척도 찾기(2026-10-04 결정): payload `scores[].name`(공백 무시)이 먼저, 그다음 `content/scale_terms.json`(검사 코드별 표현 목록, 상담사 검수 전 초안)의 표현. 결과는 그 안에서 payload 순서. 이름이 일치한 부분은 표현 검색에서 뺀다(2026-10-05: 여러 척도를 함께 보여 주면서 '정서불안정'의 '불안'이 우울/불안으로 잘못 잡히는 것을 막음).
- 척도를 못 찾았거나 찾은 척도에 T점수·범위 이름(규칙 판정, G-02)이 없으면 2·3을 빼고 조립한다. 숫자는 결과 view model(= payload)에서만 채운다(G-03).
- `SAFE_MAX_SCALES`: 3(설계값, `config`). 응답이 길어져 읽히지 않는 것을 막는다.
- 1단계에서 하지 않는 것: 섞인 질문을 나눠 설명 부분만 LLM으로 답하기(진단 우선 결정 유지), 보고서 원문 인용 구간의 출력 검증 예외.
- 노트에 저장하는 문장은 마스킹된 원래 질문이다(2026-10-04 결정). LLM의 `note_question`은 질문 뜻을 바꿀 수 있어 저장에 쓰지 않는다(필드는 7장 출력 형식에 남긴다).
- 안전 응답 종류: `diagnosis`, `parenting`, `low_confidence`(신뢰도 미달·분류 실패), `guard_fallback`(PoC2-08). 화면 표시는 '안전 응답'(G-11).

### PoC2-07 근거 제한 응답 [G-03, G-07, G-08]

```
Given intent = explain
When 응답을 생성하면
Then 프롬프트에는 정책, 기준 샘플 payload(식별 필드 제외), 척도 설명 카드, 용어사전, 마스킹된 질문만 넣고
 And 보호자 질문은 별도 태그 영역에 넣으며
 And 출력은 JSON {answerable, answer, evidence_ids, note_question} 이다

Given answerable = false 이고 answer가 빈 문자열
When 응답을 처리하면
Then "보고서에 해당 내용이 없다"는 안내 + note_saved 문구를 내보내고 질문을 노트에 저장한다

Given 마지막 시도(재생성)의 응답이 answerable = false, evidence_ids 비어 있음이고
  And answer를 비우면 출력 검증을 통과함 (근거 없이 쓴 문장 때문에만 실패)
When 응답을 처리하면
Then fallback 대신 answer를 버리고 위의 "보고서에 해당 내용이 없다" 경우와 같이 처리한다 (모델 문장은 화면에 나가지 않음, 2026-10-06)
 And 첫 시도에서는 버리지 않고 재생성한다 (근거 id를 넣은 부분 답변을 받을 기회를 남김)

Given answerable = false 이고 answer가 비어 있지 않음 (부분 답변: 보고서에 관련 사실은 있으나 질문의 일부가 없음)
When 응답을 처리하면
Then answer는 출력 검증(PoC2-08) 1~5를 모두 거치고
 And 통과하면 answer + note_saved 문구를 'AI 생성'으로 내보내며 질문을 노트에 저장한다(type = no_evidence)
```

- 부분 답변 예(기준 샘플이 아닌 회사 원본 보고서 기준): "정기적으로 다시 검사하라는데 몇 달 뒤에 하나요?" → 보고서가 '주기적 재평가'를 권장한다는 사실 + 재평가 낱말 뜻 + "시기는 보고서에 적혀 있지 않습니다" + 노트 저장. 시기를 추측하지 않는다(G-07).
- 응답 프롬프트 v2(2026-10-05) 답 순서(`CLAUDE.md` 7장):
  0) 공감: 질문에 걱정이 담겨 있으면 첫 문장에서 보호자의 마음을 받는다. 아이 상태 판단·안심 문구는 쓰지 않는다.
  1) 질문에 직접 답하는 보고서 사실: 질문이 묻는 것("사실상 같은가", "더 커진다는 뜻인가")에 대해 보고서가 적은 사실(점수, 범위 이름, 보고서 문장, 해석 시 유의사항, 용어 풀이)로 답할 수 있는 부분을 먼저 답한다.
  2) 기준선 대비 위치
  3) 상담으로 연결: 판단이 필요한 부분만 상담으로 넘긴다
  4) 지금 할 수 있는 일: 상담 준비 행동. 가능하면 근거의 카드 `behavior_examples`처럼 질문과 관련된 구체적인 장면으로 쓴다.
- 프롬프트 v2의 그 밖의 변경: 길이 4~7문장. 진단 가능성·예후 표현이 든 보고서 문장(예: "악화 가능성")은 인용하지 않고 낱말 뜻·점수로 답한다(출력 검증 실패 → fallback을 줄이기 위함, 9장 미결). 보고서 문장은 일부만 골라 인용하지 않는다(2026-10-05 사용자 결정: 앞부분만 잘라 인용하면 안심처럼 읽혀 G-01 경계를 넘음). 문장 전체를 인용할 수 없으면 인용하지 않는다.
- note_saved 문구는 코드가 붙인다(LLM이 쓰지 않음).

- 근거 묶음(`bridge.evidence`, 2026-10-04): 점수(결과 view model의 값 — 규칙 판정 범위 이름, 정의의 기준선), 보고서 서술(findings 원문), 이 아동에게 연결된 카드, 용어사전. 항목마다 `id`. 같은 입력이면 같은 텍스트(캐시 프리픽스 유지).
- 기준선까지의 차이(2026-10-06): 점수 항목의 기준선마다 코드가 계산한 `gap`(|T점수 − 기준선|)과 `side`(`below` | `at_or_above`)를 넣는다. 모델이 차이를 직접 계산하지 않고 인용하게 한다(G-03: 숫자는 코드가 원본에서 채움). T점수가 없으면 넣지 않는다.
- 응답 프롬프트 v3(2026-10-06, 답 손실 개선): v2에 더해 ① 예시를 위한 숫자를 만들지 않는다(용어 설명에 예가 필요하면 이 아이의 점수 항목을 인용) ② 두 숫자의 차이를 계산하지 않고 `gap`을 쓴다 ③ 답에 쓴 숫자마다 그 숫자가 있는 항목 id를 넣는다 ④ id는 근거 줄의 id를 글자 그대로 복사한다 ⑤ 근거로 답할 사실이 없으면 answer를 비운다(안내는 시스템이 붙임) ⑥ `<retry_feedback>`이 있으면 그 사유를 고쳐 다시 쓴다.
- 프롬프트는 검사 종류와 무관하게 쓴다. 척도 이름·기준값은 근거로만 들어간다(G-02, G-12).
- '지금 할 수 있는 일'은 상담 준비 행동(관찰 기록, 상담 질문 메모)만. 양육 방법은 쓰지 않는다(`CLAUDE.md` 6·7장).

### PoC2-08 출력 검증 [G-06] → B-4, B-6

검증 항목(모두 규칙):

1. JSON 형식과 필수 필드
2. `evidence_ids`가 비어 있지 않고, 모두 payload·카드·용어사전에 존재하는 id
3. 진단명 사전·금칙 표현 불포함
4. 응답 속 숫자가 모두 evidence 항목의 숫자 집합에 포함
5. 응답 속 범위 이름(정의 `range_labels`)이 모두 인용한 항목의 범위 이름 또는 인용한 문장에 있는 것 (2026-10-04 추가, G-02)

- 'evidence 항목'은 응답이 `evidence_ids`로 인용한 항목이다. 숫자 집합은 그 항목의 모든 값과 문장 속 숫자(`id` 제외)이며, `66.0`과 `66`은 같은 값으로 본다.
- 5의 허용 범위 이름 = 인용한 점수 항목의 `range_label` + 인용한 문장(원문·카드·용어)에 나온 범위 이름 + 기준선 라벨 중 그 기준선 값이 답에 함께 나온 것("70부터 전문 상담 권고 범위"는 허용, "66으로 전문 상담 권고 범위"는 실패).
- `answerable = false`이고 `answer`가 빈 문자열이면 1·2만 확인한다(답이 화면에 나가지 않음, `evidence_ids`는 비어도 됨). `answer`가 비어 있지 않으면(부분 답변, PoC2-07) `answerable`과 무관하게 1~5를 모두 확인한다(2026-10-05).
- 보고서 원문을 그대로 인용해도 3에 걸리면 실패로 본다(2026-10-04 결정, 예: 기준 샘플 `VI.p2`의 "가능성이 있습니다"). 빈도는 3일차 평가에서 확인한다.
- 실패 사유 코드(`format:*`, `evidence:*`, `term:<id>`, `number:<n>`, `range_label:<라벨>`)는 처리 결과에 남겨 평가 리포트에 쓴다.

```
Given 검증 1~5 중 하나라도 실패
When 처리하면
Then 1회 재생성하고(guard_result = regen)
 And 다시 실패하면 안전 응답으로 바꾸고 노트에 저장한다(guard_result = fallback)

Given 첫 생성이 검증에 실패
When 재생성을 요청하면
Then user 메시지의 보호자 질문 태그 밖에 <retry_feedback>으로 실패 사유를 코드가 쓴 문장으로 붙이고 (2026-10-06)
 And 시스템 프롬프트·근거는 첫 요청과 같으며 (캐시 유지)
 And 모델이 만든 id는 형식(영문·숫자·`.`·`_`·`-`, 40자 이하)에 맞을 때만 사유에 넣는다 (G-08)
```

- 재생성 횟수는 그대로 1회다(G-06). 같은 요청을 다시 보내면 같은 실수를 반복하는 경우가 많아(Haiku 다샘플 평가에서 재생성 성공률 약 18%) 사유를 알려 준다.

### PoC2-11 질문 정리

```
Given 노트에 저장된 질문 목록
When 브리프를 만들기 전에 정리하면
Then 정리 LLM을 1회 호출해 중복을 합치고 유형을 붙인 목록을 받고
 And 원래 질문(source_turn_id)과의 연결을 유지한다
```

- 의미가 바뀐 질문 0건은 `eval/organize_samples.jsonl`로 사용자가 수동 확인한다(3일차).
- 세부(2026-10-04 결정):
  - 유형: `diagnosis`(진단·치료·경과) / `parenting`(양육) / `understanding`(결과·용어 이해) / `other`(기타). 화면·브리프에는 'AI 정리(검수 전)'로 표시(G-11).
  - 입력은 마스킹된 노트 문장과 id만(보고서 없음, G-09). 노트가 0건이면 호출하지 않는다. `llm_calls`에는 `turn_id` 없이 `stage = organize`로 남긴다.
  - 검증(모델과 무관한 규칙): 형식, 모든 노트가 정확히 한 항목에 들어감(빠짐·중복·입력 밖 id 없음), 원래 질문에 없던 금칙 표현·숫자가 새로 생기지 않음. 보호자가 쓴 진단명은 상담사가 알아야 할 걱정이므로 남아도 된다(G-01은 AI가 새로 말하는 것을 막는다).
  - 실패하면 1회 재생성(P-03), 다시 실패하거나 API 오류면 정리 없이 노트 1건 = 항목 1개로 쓴다(유형: diagnosis→diagnosis, parenting→parenting, no_evidence·guard_fallback→understanding, 그 밖→other).
  - 항목의 원래 질문 연결(`source_turn_id`)과 관련 보고서 항목(`related_refs`)은 코드가 원래 노트에서 채운다.

### PoC2-12 브리프 텍스트 (M3)

```
Given 대화와 노트가 쌓인 상태
When 브리프를 출력하면
Then 텍스트에 ① 보호자 질문(유형별, 관련 보고서 항목 id·이름) ② AI가 답한 설명형 질문과 응답 ③ 위기 표시 를 담고
 And 보고서 점수·보호자 의견을 다시 나열하지 않는다
```

- 출력: CLI(`python -m bridge.brief <result_id> [--no-llm]`)와 Streamlit에서 텍스트로 표시. 별도 화면 UI 없음.
- ②의 'AI가 답한 설명형 질문'은 route = answer, guard_result ∈ {pass, regen}, 노트 미저장(= 답이 나간 것)인 턴이다. ①의 관련 항목은 근거 묶음에서 코드가 'id · 이름'으로 채운다.
- 브리프는 LLM 없이 코드가 조립한다(정리 결과만 LLM).

### PoC2-13 기록

- 모든 질문: `qa_turns` 1행(입력 검증 실패는 저장하지 않음). `route`(input_error 제외: crisis / safe / redirect / answer / api_error, 2026-10-04 추가 / note: 결과 화면의 상담 질문 저장, PoC1-11, 2026-10-05 추가)를 함께 남긴다. 모든 LLM 호출: `llm_calls` 1행(stage, model, prompt_version, 입력 토큰, cached_tokens(캐시 읽기), cache_write_tokens, 출력 토큰, stop_reason, latency_ms, cost_usd).
- `cost_usd`는 `config` 단가로 계산한다: 입력 × 단가 + 캐시 쓰기 × 단가 × 1.25 + 캐시 읽기 × 단가 × 0.1 + 출력 × 출력 단가.
- API 오류 재시도는 SDK 재시도(`max_retries` = P-05 횟수)로 하고, 최종 실패한 호출은 `llm_calls`에 남기지 않는다(토큰·비용 없음).

### 6-1. 기준 평가

- CLI: 모델과 프롬프트 세트를 지정해 `eval/questions.jsonl` 전체를 기준 샘플로 실행한다(`--prompt-set v1|v2|v3`, 기본은 현재 버전 v3). 세트는 응답 프롬프트 버전으로 이름 짓고(v3 = intent_v2 + answer_v3), 지난 세트는 고정해 이전 결과와 비교할 수 있게 둔다.
- 결과: `eval/reports/<날짜>_<모델>_<세트>.md`와 같은 이름의 `.json`(비교표 입력) — B-4~B-6 통과 여부, 문항별 route·guard_result·실패 사유·의도 신뢰도, 토큰·비용·응답 시간 합계.
- 불안 해소(1-1): R-2·R-4는 자동 채점해 리포트에 적는다. R-1·R-3은 리포트의 응답 전문에 사용자가 예/아니오를 적는다. 프롬프트 v1·v2를 같은 모델로 한 번씩 실행해 비교한다.
- 평가셋에 보고서 권고 행동 질문(`tags: report_action`)을 `explain` 15문항 안에 3문항 이상 넣는다(R-4).
- 양육 조언형은 별도 유형으로 두지 않고 `diagnosis` 15문항 안에 `tags: parenting`으로 3문항 넣는다(기획안 4유형 구성 유지, 처리 경로가 같은 `safe`, 2026-10-06).
- 평가는 임시 DB에서 실행해 데모 DB(`bridge.db`)에 기록을 섞지 않는다.

## 7. 콘텐츠 작성 규칙

- 형식은 `content/README.md`를 따른다.
- 문장에 숫자를 직접 쓰지 않는다. 숫자는 자리표시자(`{t}`, `{percentile}`)로 두고 코드가 채운다(G-03).
- 숫자 자리표시자 바로 뒤에 조사를 두지 않는다(숫자 읽는 소리에 따라 '로/으로' 등이 달라짐). 단위를 붙여 조사를 고정한다: `T점수 {t}점으로`, `{rank_from_top}%에`, `{max_chars}자 이내`(2026-10-05, 테스트로 확인).
- 진단명, 치료·약물·기관 이름, 예후 표현, "괜찮다/걱정 없다/심각하다" 같은 안심·위협 판단을 쓰지 않는다(G-01).
- 카드 문장은 보고서의 권고 수준을 넘지 않는다(예: 보고서가 "관찰 권고"면 카드도 관찰 권고까지만).
- 낱말 풀이(PoC1-10)는 객관적인 뜻만 쓴다. 긍정·부정으로 풀이하지 않는다: 안심·완화 문구("~라는 뜻은 아닙니다", "정해진 것은 아닙니다"), 좋고 나쁨의 평가, 이 아이에게 해당한다는 단정(예: 낱말 풀이에 "이런 모습이 또래보다 많이 보고되었다")을 쓰지 않는다. 점수 방향의 정의("점수가 높을수록 …")는 객관적 정보다(2026-10-05, `CLAUDE.md` G-01).
- 공감 문장(안전 응답 `empathy`, 응답 프롬프트 0단계)은 보호자의 마음을 받는 문장만 쓴다(예: "결과를 보고 여러 가지가 마음에 걸리셨을 것 같아요"). 아이 상태에 대한 판단, 안심·완화 문구("괜찮다", "걱정하지 않으셔도 된다", "~라는 뜻은 아니다")는 쓰지 않는다. 공감 문장은 G-01의 안심 판단에 해당하지 않는다(2026-10-05 사용자 결정).
- LLM으로 초안을 만들 수 있지만, 저장 상태는 모두 `draft`로 둔다.
- 위기 안내의 공공 상담 채널 연락처는 공식 출처를 확인한 뒤 출처와 확인일을 함께 적는다.
